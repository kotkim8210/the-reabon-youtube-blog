## 1. 제품 개요

### 한 줄 요약
브랜드 유통/리셀 셀러(크림·포이즌·무신사)가 **감이 아니라 데이터로 소싱**하고, **직원과 함께 구매→입고→발송을 실수 없이** 돌리게 해주는 웹 SaaS.

### 해결하는 문제
영상에서 확인된 실제 페인포인트 그대로:

| # | 페인포인트 (영상 근거) | 해결 |
|---|---|---|
| 1 | 무신사에서 상품마다 쿠폰·카드할인 계산 → 크림 탭 열어 시세 확인 → 수기 마진 계산 반복 ("딸깍딸깍 Ctrl+C/V 미친듯이") | 시세 비교 대시보드: 매입가·크림가·마진율·판매량 자동 계산 |
| 2 | 크림 총매물(뒷물량)을 볼 수 없어서 "사기만 하면 가격이 무너지는" 이유를 모름 | 총매물 ÷ 월판매량 = 소진 개월 수 노출 |
| 3 | 역대 최저가를 모르고 고점에 매입 → 물림 | 체결가 그래프 + 최저가 방어선 표시 |
| 4 | 도매 오퍼 리스트(카톡 캡처)를 하나하나 검색해 마진 검증 | 스크린샷 붙여넣기 → AI가 품번·가격·수량 추출 → 시세 자동 매칭 |
| 5 | 다계정(10~20개) 구매 장부를 엑셀 수기 작성 | 구매내역 자동 수집 + 계정별 등급/마일리지 표시 |
| 6 | 1,000개 사면 몇 개 안 온 걸 몇 주 뒤에 앎 (누락·도난·오배송) | 도착예정 큐 + 모바일 송장 스캔 2단계 검수 |
| 7 | 송장번호 수기 입력 오타 → 크림 페널티 ("20개 중 1개는 무조건 틀림") | 판매주문 통합 조회 + 송장 바코드 스캔 일괄 발송 |

### 핵심 가치
- **"안 잃는 소싱"**: 뒷물량·최저가·판매속도를 보고 사면 물리지 않는다 (영상의 핵심 철학: "돈을 못 벌어도 되는데 절대 잃으면 안 된다").
- **직원 위임 가능한 운영**: 대표·직원·3PL 창고관리자가 단계를 나눠 쓰는 기업형 설계 (월매출 1억 이상 규모 대응).
- 기존 대안(엑셀 + 크림 앱 수동 검색 + 카톡)과 달리 **소싱 판단→구매→입고→발송이 한 시스템**에서 이어진다.

## 2. 사용자

### 주요 사용자
- **누구**: 브랜드 유통/리셀 셀러. ① 부업 초보(저녁 8시~새벽 2시 활동), ② 직원 1~5명 둔 기업형 셀러(월매출 1천만~1억+), ③ 3PL 창고관리자·직원(제한 권한)
- **상황**: PC로 소싱 판단(낮/밤), 모바일로 창고·문앞에서 입고 스캔(아침), 편의점에서 발송 처리
- **목표**: 마진 검증 시간 단축, 재고 물림 방지, 입고 누락 0건, 플랫폼 페널티 0원

### 사용자 시나리오
1. **소싱(대표)**: 도매 카톡 리스트를 캡처해 붙여넣기 → AI 분석 → "월판매 3,000개 vs 수량 770개 = 1개월 내 소진, 마진 9.8%" 확인 → 매입 결정
2. **입고(직원)**: 아침에 택배 더미 앞에서 폰으로 송장 연속 스캔(도착 처리) → 사무실에서 재스캔 → 화면에 뜬 주문 내용물과 대조 → 정상/오배송 기록
3. **발송(직원)**: 크림 3개 계정 판매 주문을 한 테이블로 조회 → 같은 상품끼리 포장 → 편의점에서 송장 바코드 스캔 → 일괄 발송 처리

## 4. 사용자 흐름 (User Flow)

### 핵심 흐름
```
[소싱] 시세비교/도매분석 → 마진·물량 확인 → (외부 구매) → [장부] 구매내역 → 입고관리 추가
     → [모바일] 도착 스캔 → 검수 스캔 → 입고완료/이슈 → [발송] 주문조회 → 송장스캔 → 일괄발송
```

### 상세 흐름
1. **소싱 판단**: 시세 비교 표에서 마진율·월판매·총매물 확인 → 시세 상세(그래프·최저가·시나리오별 마진·사이즈별 매물)
2. **구매 기록**: 구매 건 등록(Phase 1: 주문내역 붙여넣기/CSV, Phase 2+: 확장프로그램 반자동) → 개인용 구매는 제외 처리
3. **입고**: 선택 건 "입고 관리에 추가" → 도착예정 큐 → 모바일 스캔 2단계(도착→검수) → 이슈 건은 별도 큐로
4. **발송**: 판매주문 가져오기 → 동일상품 그룹핑 → 송장 스캔 → 플랫폼별 발송 파일/등록

## 5. 성공 기준

- [ ] 상품 1개 마진 검증 시간: 수동 5분 → 10초 이내 (시세 카드 클릭 1회)
- [ ] 입고 누락·오배송 감지율 100% (도착예정 대비 미도착 자동 경고)
- [ ] 송장번호 수기 입력 0건 (스캔 입력률 100%) → 플랫폼 페널티 0원
- [ ] 직원 계정으로 입고·발송 처리 가능 (대표 없이 아침 입고 완료)
- [ ] 도매 리스트 AI 추출 정확도 95%+ (오추출은 셀 단위 수동 수정으로 보정)
- [ ] 실사용: 본인 사업 4주 운영에서 엑셀 장부 완전 대체

## 6. 안 만드는 것 (Out of Scope)

> 이 목록에 있는 건 Phase 1에서 만들지 않습니다. AI에게 코드를 시킬 때 이 목록을 함께 공유하세요.

- **크림 자동 크롤링 봇** — 이유: 공식 API 없음 + 약관 위반·민사(DB권/부정경쟁) 리스크(잡코리아 v. 사람인 판례 계열). 시세는 Phase 1에서 수동/반자동 입력, 자동화는 Phase 3에서 법률 검토 후.
- **자동 입찰/최저가 경쟁 매크로** — 이유: (1) 웹이 아닌 **별도 데스크톱(Electron) 앱**이 필요해 코드베이스가 다름, (2) 크림 약관상 자동화 금지 → 계정 정지 리스크. 단, **이게 벤치마크 제품(넘버원 셀러센터)의 실제 유료 매출원**이므로 "영원히 제외"가 아니라 **웹 MVP 검증 후 별도 데스크톱 트랙**으로 분리(06_BENCHMARK_ANALYSIS §7 참고). 탐지 회피·안티봇 우회 기능은 만들지 않음.
- **네이티브 모바일 앱** — 이유: 반응형 웹 + WASM 바코드 스캔으로 충분 (리서치 확인). 앱스토어 심사·배포 비용 불필요.
- **결제/요금제** — 이유: Phase 1은 본인 사용. 상용화는 Phase 3.
- **StockX 등 해외 플랫폼 연동** — 이유: 국내 크림·포이즌 흐름 먼저 검증.
- **재고 회계/세무 신고 기능** — 이유: 부가세 환급은 "시나리오 계산"까지만. 신고는 세무사 영역.
