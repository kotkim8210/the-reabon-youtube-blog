> 분리 원칙: **법적 리스크가 없는 자체 데이터 기능(장부·입고)부터**, 외부 데이터 의존 기능(시세 자동화)은 뒤로.

## 매크로(자동입찰) 트랙은 언제? — "완전 초짜"에게 주는 답

**결론: 지금은 아님. 최소 Phase 2 이후, 그리고 아래 3개 조건이 다 충족될 때.** 이유 = 매크로는 "이미 재고를 쌓고 판매 리스팅을 돌리는 사람의 시간을 아끼는" 도구인데, 초짜는 아직 자동화할 재고·리스팅 자체가 없다. 자동입찰·최저가경쟁을 켤 물건이 없는데 매크로부터 만들면 순서가 거꾸로다.

**착수 트리거 (셋 다 만족 시):**
1. 웹 MVP(장부·입고·마진)를 본인 사업에 **2~4주 실사용**해서 소싱 판단이 실제로 빨라졌다.
2. 크림 **판매 리스팅이 상시 수십 건 이상** 돌아 수기 리프라이싱이 번거로워졌다 (= 자동화할 대상이 생김). 대략 크림 등급 **레벨1 탈출(월 정산 200만원+) 근처**.
3. 매크로가 크림 약관 위반 → **계정 정지 리스크를 감수**하겠다는 판단이 섰다 (초짜 계정이 정지되면 타격이 큼 — 그래서 더더욱 나중).

그 전까지는 **매크로 무료 기능(입찰관리·판매내역/발송 다운로드)** 수준만 웹으로 흡수하고, PRO 자동화(보관 매크로·최저가 경쟁·동시 입찰)는 별도 Electron 트랙으로 미뤄둔다. 예상 시점: **본 로드맵 Phase 3와 병행 또는 그 이후**.

## Phase 1: MVP — "장부와 입고가 도는 내부 툴" (예상 3~4주)

### 목표
엑셀 장부를 완전히 대체한다. 구매를 기록하고, 모바일로 송장을 스캔해 도착·검수하고, 마진 계산기로 소싱을 검증할 수 있다.

### 기능
- [ ] 로그인 (Supabase Auth 이메일 매직링크) + 워크스페이스/멤버(owner·staff·warehouse 역할)
- [ ] 상품 마스터: 품번 기준 등록·검색 (F4)
- [ ] 마진 계산 엔진 (F1): fee_rules 시드 데이터(크림 2026-03 개편: 기본 2,500원 + 레벨별 5.5~6%) + 매입가 입력 → 일반/부가세환급(10/110 공제)/포이즌(수수료 5%+이체 1%+작업비, 영세율) 시나리오
- [ ] 시세 카드: 시세·매물·판매량 **수동 입력** + 스냅샷 저장 → 마진율·소진개월 자동 계산
- [ ] 구매내역 (F3): 수동 등록 + 주문내역 텍스트/CSV 붙여넣기 파싱, 계정별 필터, 개인용 제외, "입고 관리에 추가"
- [ ] 입고 관리 (F2): 도착예정→도착→검수→완료/이슈 파이프라인 (PC 테이블 + 상태 카운터)
- [ ] 모바일 송장 스캔: `barcode-detector`(zxing-wasm 포니필, iOS Safari 필수 대응) 연속 스캔 → 도착 처리 / 재스캔 → 품목 검수(정상·수량부족·오배송·불량)
- [ ] 연동계정 관리: 계정 라벨·등급·마일리지 수동 기록 (자격증명 저장은 아직 안 함)

### 데이터
- workspaces, members, linked_accounts, products, market_snapshots, price_history(수동), fee_rules, purchases, inbound_parcels, inbound_items

### 인증
- Supabase Auth (이메일 매직링크). 역할별 화면 제한: warehouse는 입고 관리만.

### "진짜 제품" 체크리스트
- [ ] 실제 DB 연결 (목업 데이터 X)
- [ ] 실제 인증 (하드코딩된 비밀번호 X)
- [ ] 실제 서버에 배포 (localhost X) — Vercel
- [ ] 다른 사람이 URL로 접속해서 써볼 수 있음 (본인 폰에서 실제 택배 송장 스캔 테스트 통과)

## Phase 2: 확장 — "AI 분석과 발송" (예상 3~4주)

### 전제 조건
- Phase 1이 안정적으로 배포되어 본인 사업 장부로 2주 이상 실사용됨

### 목표
도매 리스트를 캡처 한 장으로 검증하고, 판매 주문을 스캔으로 발송 처리한다.

### 기능
- [ ] 도매 리스트 AI 분석 (F5): 이미지 붙여넣기 → Claude API vision + Structured Outputs(JSON Schema 강제) → 품번·가격·사이즈별 수량 추출 → confidence 낮은 셀 하이라이트 + 수동 수정 → 상품 매칭 → 마진·소진 계산. 일일 횟수 제한(비용 가드)
- [ ] 발송 관리 (F6): 판매자센터 엑셀 업로드로 주문 통합 → 동일상품 그룹핑 → 모바일 송장 스캔 → 발송 상태 기록 + 플랫폼 업로드용 파일 생성
- [ ] 시세 반자동 수집: 크림 상품 페이지 "붙여넣기 파서" 또는 스크린샷 AI 추출 (본인이 보는 화면을 본인이 기록 — 크롤링 아님)
- [ ] 체결가 그래프 + 역대 최저가 방어선 표시
- [ ] 구매내역 이메일 파싱 실험 (주문 확인 메일 → 자동 등록; 알림톡 위주 몰은 커버리지 낮음을 감안)

### 추가 데이터
- wholesale_analyses / wholesale_analysis_rows, sales_orders

### 통합 테스트
- Phase 1 기능(장부·입고) 정상 동작 회귀 확인, AI 추출 정확도 실측(도매 캡처 20장 기준 95%+)

## Phase 3: 고도화 — "데이터 파이프라인과 상용화" (예상 6~8주)

### 전제 조건
- Phase 1+2가 안정 운영, 시세 데이터 수급 전략에 대한 법률 검토 완료

### 목표
시세가 자동으로 갱신되고, 다른 셀러를 태울 수 있는 SaaS가 된다.

### 기능
- [ ] 시세 자동 수집 (F7): **벤치마크(NO1) 확인된 방식 = 로컬 프로그램이 사용자 본인 크림/포이즌 계정에 로그인해 수집**(06_BENCHMARK §5). 내부 툴이므로 이 방식을 따라감 — 우선순위 ① **본인 크림 세션 읽는 브라우저 확장/로컬 스크립트**(수집 주체=사용자 본인, 가장 단순·현실적) ② 포이즌 공식 오픈플랫폼 API(입점 시) ③ 서버 크롤링은 채택 안 함(DB권 리스크). Fly.io 워커는 스케줄링·저장용으로만
- [ ] 입찰 대기열 조회 (F8): 희망가 구간 판매입찰 수
- [ ] 계정 자격증명 Vault 저장 + 등급/마일리지 자동 갱신
- [ ] 멀티테넌트 상용화 (F9): 워크스페이스 초대, 요금제(무료: AI 분석 5회/일 제한 — 영상 프로그램과 동일한 앵커), 토스페이먼츠 결제
- [ ] 인앱 채팅 상담(AI 챗봇 + 사람 연결) — 영상 프로그램의 지원 구조

### 주의사항
- **비용**: Claude vision 호출당 비용, Fly.io 워커 상시 비용, 시세 데이터 저장 용량 증가
- **리스크**: 크림 무단 수집 데이터의 상업적 재판매는 민사 리스크 최대 시나리오 — 반드시 법률 자문 후 진행. 사용자 계정 기반 자동화는 계정 정지 위험을 약관에 고지
- **외부 의존**: 플랫폼 사이트 개편 시 파서 깨짐 → 구조 변경 감지 알림 필수
