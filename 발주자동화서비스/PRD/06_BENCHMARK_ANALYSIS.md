## 5. 아키텍처 발견 — 왜 하이브리드인가

**설치파일 분석 결과: 데스크톱 앱은 Electron 기반** (291MB NSIS 인스톨러 내부에서 `electron.exe` 바이트 확인).

**백엔드 확인: Supabase** — 웹 소싱툴 로그인 페이지가 `https://aibdxsebwhalbnugsqel.supabase.co/auth/v1/user`(Supabase Auth)를 호출함(2026-07-04 네트워크 분석). 즉 벤치마크 제품은 실제로 **Supabase 기반**이며, 이는 우리 04_PROJECT_SPEC의 스택 선택(Next.js+Supabase)이 옳았다는 실증. (프로젝트 ref: `aibdxsebwhalbnugsqel`) · 분석/트래킹 = Matomo(self-host `matomo.chnprice.com`) + GA4.

### 데이터 수집 방식 = 로컬 PC 프로그램 (✅ 확정, 2026-07-04 실측)

우리 최대 질문("크림/포이즌 시세를 서버 크롤링? 사용자 세션?")의 **답: 사용자 세션을 로컬에서 구동하는 방식**. 근거:

1. 웹 소싱툴 **'판매처 연동'** 화면 진입 시 모달: **"PC 프로그램 연결 대기 중 — No1 Seller Center를 실행해 주세요. 실행되면 자동으로 연결됩니다."** → 웹은 UI일 뿐, 실제 플랫폼 접근은 **사용자 PC의 Electron 데스크톱 앱**이 담당하고 웹이 그 로컬 앱과 페어링됨(로컬 브리지, 추정 ws://127.0.0.1).
2. 계정 연동 이용가이드(miricanvas)는 사용자에게 **크림 비밀번호를 "이메일+비밀번호" 방식으로 바꾼 뒤 그 아이디/비번을 NO1에 입력**하라고 안내 → 로컬 앱이 그 자격증명으로 **사용자 본인 크림 계정에 로그인**해 조회·입찰·리프라이싱 수행.
3. '판매처 연동' 화면은 크림(개인/입점)·포이즌·솔드아웃·무신사·29CM·롯데온·SSF별로 **아이디저장/비번저장/자동로그인** 토글 제공 = 각 플랫폼 자격증명을 위탁받아 로컬에서 로그인.

**함의**: 서버 크롤링이 아니라 **각 유저가 자기 계정에 로컬에서 접근** → 공개 API 크롤링의 DB권/부정경쟁 리스크를 회피하는 대신, (a) 플랫폼 비밀번호를 위탁받는 **보안 부담**과 (b) 자동화로 인한 **계정 정지 리스크**를 유저가 감수. 이게 NO1이 데스크톱 앱을 반드시 배포하는 이유.

핵심은 **"왜 소싱은 웹으로 되는데 매크로는 데스크톱 전용인가"** 입니다.

| 기능 | 웹으로 가능? | 이유 |
|---|---|---|
| 시세 분석·재고 조회·마진 계산 (소싱툴) | ✅ 웹 OK | 데이터 조회·표시 위주. 영상이 웹으로 시연한 이유 |
| 입찰관리·다운로드 (매크로 무료) | ✅ 대체로 웹 OK | 파일 생성·상태 관리 |
| **자동 입찰 / 최저가 경쟁(리프라이싱) / 보관 매크로 (PRO)** | ❌ 데스크톱 필수 | 크림/솔드아웃 세션을 **지속적으로 구동·반복 제어**해야 함. 브라우저 샌드박스로는 불가 → 네이티브(Electron) 프로세스가 필요 |
| 입점 OTP 자동입력 | ❌ 모바일앱 | 폰의 OTP 앱/알림 접근 |

> 즉, **우리가 영상 보고 만들려던 것(웹 소싱·장부·입고)은 웹으로 충분**하지만, **실제 매출을 내는 PRO 매크로는 별도 데스크톱 앱**이 필요합니다. 이게 이 제품 아키텍처의 핵심 교훈입니다.

## 7. 우리 클론 전략에 주는 시사점 (PRD 재조정)

### (A) 기존 PRD가 맞은 부분
- 웹(Next.js+Supabase)으로 **소싱·시세·장부·입고·발송**을 만드는 방향은 정확. 영상이 시연한 무료 웹툴이 정확히 이 범위.
- 무료 티어로 유저를 모으는 freemium 전략도 일치.

### (B) 재조정이 필요한 부분 — 매크로 스코프
기존 04_PROJECT_SPEC에서 "자동 매크로 절대 만들지 마"라고 했는데, 이는 영상만 봤을 때(웹 전용으로 오판)의 판단이었습니다. **실제 벤치마크의 유료 매출원은 바로 그 매크로**입니다. 재조정:

- **매크로는 별도 데스크톱 트랙(Electron)** 으로 분리. 웹 클론과 코드베이스가 다름.
- **이건 P3 이후 또는 별도 프로젝트**로. 웹 MVP(장부·입고·소싱)를 먼저 검증한 뒤 착수.
- ⚠️ **리스크 고지(그대로 유효)**: 크림 이용약관은 "자동화된 수단"을 금지 → **매크로 사용 계정은 정지 위험**. 벤치마크 제품도 이 리스크를 유저가 감수하는 구조. 클론을 상용화하려면 이 점을 약관에 명시하고, 사용자 본인 계정 자동화(본인 리스크)임을 분명히 해야 함. **탐지 회피/안티봇 우회 목적의 기능은 만들지 않음** — 자동화 자체와 회피는 다른 문제.

### (C) 새로 반영할 기능
- **입점 OTP 자동입력**(다계정 로그인 편의) — 다계정 운영 셀러의 실제 페인. 모바일 트랙에서 고려.
- **"현영 양식" 판매내역 다운로드** — 특정 회계/정산 양식 지원. 우리 발주서 자동화 경험과 연결 가능.
- **매출/마진 시뮬레이터** 독립 메뉴.
