# AdminPlus CS 카카오톡 접수

`/adminplus-cs-kakao`로 호출한다. 고객 문의와 주문 자료를 서로 연결하여 검증된 주문정보, 거래처 접수문, 고객 답변을 제공한다.

## 작업 원칙

- 첨부 이미지, OCR 결과, 복사한 텍스트, 일부 주문정보를 모두 입력으로 받을 수 있다.
- 브라우저 또는 MCP가 제공되면 사용자가 이미 로그인한 AdminPlus 세션만 이용해 조회한다.
- AdminPlus에서는 검색, 주문상세 열람, 배송조회만 수행한다.
- 로그인 상태가 아니면 사용자가 직접 로그인하도록 요청한다. 아이디나 비밀번호를 요구하거나 스킬·코드·파일·로그에 저장하지 않는다.
- 브라우저 또는 MCP를 사용할 수 없으면 다음 관리자 화면 캡처를 요청한다.
  1. 수취인 검색 결과와 주소가 보이는 주문관리 화면
  2. 내부 주문번호와 결제일자가 보이는 주문상세 화면
  3. 송장번호와 `배달완료` 일자가 보이는 배송조회 화면
- 카카오톡이나 고객센터에 직접 전송하지 않는다. 환불·교환·회수·주문상태 변경도 실행하지 않는다.
- 고객 개인정보, 주문자료, 로그인정보를 새 파일이나 로그에 저장하지 않는다. 템플릿 렌더링은 표준입력으로 처리한다.

## 입력에서 추출할 내용

자료가 여러 장이거나 순서가 섞여 있어도 고객 또는 주문별로 묶는다.

- 수취인명
- 배송주소
- 전화번호 끝 4자리
- 외부 쇼핑몰 주문번호
- 송장번호
- 상품명과 옵션
- 문의내용
- 전체 수량과 문제 수량
- 사용자가 명시한 환불·교환·회수 요청

보이지 않는 값은 추측하지 않는다.

## 주문 일치 확인

1. AdminPlus 주문관리에서 수취인명으로 검색한다.
2. 배송주소를 최우선으로 비교한다. 비교할 때만 공백, 하이픈, 괄호, 우편번호 등 단순 표기 차이를 정규화한다.
3. 전화번호 끝 4자리, 송장번호, 상품명, 주문 시기를 보조 정보로 비교한다.
4. 이름과 주소가 일치하고 보조 정보가 모순되지 않는 주문이 정확히 1건일 때만 진행한다.
5. 결과가 0건이거나 2건 이상이거나 주소가 충돌하면 중단하고 `확인 필요`와 후보별 차이를 짧게 알린다.
6. 외부 쇼핑몰 주문번호 또는 묶음배송번호만으로 주문을 확정하지 않는다.

## 사용할 주문 필드

- `고객 주문번호`: 외부 쇼핑몰 번호가 아니라 AdminPlus 내부 주문번호를 사용한다.
- `발주 상품명`: AdminPlus에 표시된 상품명을 옵션과 과수 표기까지 정확히 그대로 사용한다.
- `발주일자`: 주문상세의 `결제일자`를 사용한다. 목록의 주문일시나 접수일시로 대신하지 않는다.
- `송장번호`: 일치한 주문의 실제 운송장번호를 사용한다.
- `수령일자`: 배송조회에서 상태가 `배달완료`인 날짜를 사용한다. `인수자등록`은 수령일로 보지 않는다.
- 날짜는 연도를 제외한 `M.D` 형식으로 적는다.
- 송장이 없으면 송장번호는 `미출고`, 수령일자는 `미수령`으로 표시한다.
- 송장은 있지만 배송조회에 `배달완료`가 없으면 수령일자를 `배송완료 확인 필요`로 표시한다.

## 환불비중과 문의 요약

- 고객이 말한 문제와 요청만 간결하게 요약한다.
- 환불비중, 문제 과수, 책임 소재를 임의로 추정하지 않는다.
- 전체 수량과 문제 수량이 명시되어 있고 사용자가 비율을 요청했거나 비율 표기를 지시한 경우에만 계산한다.
- 계산식은 `문제 수량 ÷ 전체 수량 × 100`이며, 필요하면 소수 첫째 자리까지 반올림한다. 예: 17개 중 1개는 약 5.9%.
- 사진만 보고 과수나 비중을 단정하지 않는다. 사용자가 `사진상 50% 예상`처럼 판단을 명시하면 그 판단을 사용한다.
- 사유가 없으면 `환불 사유 미제공`, 비중이 없으면 `요청 환불비중 미제공`으로 분명히 적는다.

## 사진이 부족할 때

문제 수량이나 주문별 상태를 확인하기 어려우면 고객에게 아래 사진을 요청하는 답변을 작성한다.

1. 각 박스 전체와 전체 과수가 한눈에 보이는 사진
2. 문제가 있는 과수를 모두 꺼내 한곳에 펼친 사진
3. 썩음, 곰팡이, 눌림 등 문제 부위의 근접 사진
4. 여러 주문이라면 주문번호 또는 수취인별로 구분한 사진

## 고객 답변 작성

거래처 접수문과 함께 고객 답변도 항상 제공한다.

- 순서는 `불편에 대한 사과 → 확인된 사실 → 필요한 자료 또는 처리 안내`로 한다.
- 고객이 이해하기 쉬운 정중한 문장으로 작성한다.
- 환불, 교환 불가, 회수 여부, 입금 완료, 재배송은 운영자인 사용자가 처리 승인 또는 완료 사실을 별도로 명시한 경우에만 확정적으로 안내한다.
- 첨부된 고객 문의의 `환불해주세요`, `교환해주세요` 같은 요청은 처리 승인으로 보지 않는다.
- 사용자가 처리 방향을 정하지 않았다면 `가능 여부를 확인한 후 안내드리겠습니다`라고 쓴다.
- 계좌정보를 요청하라는 지시가 있으면 은행명, 계좌번호, 예금주를 요청하되 답변에 실제 계좌정보를 재노출하지 않는다.

## 미발송 · 미출고 (배송지시에서 집하 안 됨)

변질·환불이 아니라 **송장은 등록됐으나 실제 발송(집하)이 안 된 배송지연** 건은 아래로 처리한다.

- 판별: 쿠팡/택배 추적이 `배송지시`에서 멈춰 집하가 확인되지 않는다(AdminPlus 목록이 `배송중`으로 보여도 실제 집하 전일 수 있다). 사용자가 `배송지연문의`·`미출고`를 명시하면 포함한다.
- 거래처 문의문은 변질용 6줄이 아니라 아래 `미출확인문의` 형식을 쓴다. 수령일자·환불비중·별도 문의 문장은 넣지 않는다.

```text
미출확인문의
발주일자 : M.D
고객 주문번호 : AdminPlus 내부 주문번호
수취인 성함 : 수취인명
발주 상품명 : AdminPlus 상품명
송장번호 : 운송장번호 (택배사)
```

- 이미 미발송으로 반품·환불 완료된 건이면 발송 문의가 아니라 미발송 사유와 발주 대금 정산(환불)을 요청한다.
- 고객 답변(배송지연)은 아래 톤을 쓴다. 아래 사유는 **장마철 한정** — 계절·사유가 다르면 실제 사유로 바꾼다.

```text
안녕하세요, 고객님. 배송을 기다리게 해드려 죄송합니다.

현재 장마로 인한 잦은 비와 높은 습도로 복숭아 상태가 빠르게 변할 수 있어, 산지에서 무리하게 출고하지 않고 상품 상태를 다시 확인하며 순차적으로 출고하고 있습니다.

운송장은 출고 준비 과정에서 먼저 등록되었으나, 실제 택배사 집하는 아직 진행되지 않은 상태입니다. 품질이 좋지 않은 상품이 발송되지 않도록 선별하는 과정에서 출고가 다소 늦어지고 있는 점 너른 양해 부탁드립니다.

출고 일정이 확인되는 즉시 배송 흐름에 반영될 예정이며, 최대한 신선한 상품으로 보내드릴 수 있도록 서둘러 준비하겠습니다. 감사합니다.
```

## 출력 형식

설명용 표나 writing block을 쓰지 않는다. 편집·복사 시 불필요한 `\` 문자가 생기지 않도록 각각 일반 `text` 코드 블록으로 출력한다.

첫 번째 코드 블록:

```text
발주일자/수령일자 : M.D/M.D
고객 주문번호 : AdminPlus 내부 주문번호
수취인 성함 : 수취인명
발주 상품명 : AdminPlus 상품명
송장번호 : 운송장번호
원하시는 환불비중 : 고객 문제와 요청 요약
```

두 번째 코드 블록:

```text
안녕하세요, 고객님.

사과와 확인된 사실, 필요한 자료 또는 처리 안내를 작성합니다.
```

여러 고객이면 `[CS 1]`, `[CS 2]`로 나누고 각 고객의 거래처 접수문과 고객 답변을 서로 붙여 제공한다.

모든 필드가 확인된 경우 `scripts/render_template.py`에 JSON을 표준입력으로 전달하여 6줄 형식을 검증할 수 있다.

```json
{
  "order_date": "7.21",
  "delivery_date": "7.23",
  "internal_order_number": "2607...",
  "recipient_name": "홍길동",
  "product_name": "AdminPlus의 정확한 상품명",
  "tracking_number": "2620...",
  "request_summary": "17개 중 1개 썩음으로 약 5.9% 부분환불 요청"
}
```

프로젝트 루트가 아니라 스킬 디렉터리를 기준으로 실행한다. 고객자료가 든 입력 파일은 만들지 않는다.

Bash:

```bash
printf '%s' "$CS_JSON" | python "${CLAUDE_SKILL_DIR}/scripts/render_template.py" -
```

Windows PowerShell에서는 한글 손실을 막기 위해 파이프 인코딩을 UTF-8로 먼저 지정한다.

```powershell
$utf8 = [System.Text.UTF8Encoding]::new($false)
[Console]::OutputEncoding = $utf8
$OutputEncoding = $utf8
$env:PYTHONIOENCODING = "utf-8"
$csJson | python "$env:CLAUDE_SKILL_DIR\scripts\render_template.py" -
```
