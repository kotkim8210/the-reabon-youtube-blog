> **버전:** v1.0 · **작성일:** 2026-06-03

## 0. 핵심 요약 (TL;DR)

- **요금제를 2단(Free/Pro)에서 4단(Free / Starter / Pro / Business)으로 재설계한다.** 앵커(Business)와 디코이(Starter) 구조로 Pro를 "가장 합리적인 선택"으로 만든다.
- **Pro 가격을 ₩29,000 → ₩39,000/월로 인상**하되 Starter(₩19,000)를 신설해 가격 민감 셀러의 이탈을 막는다. 기존 Pro 사용자는 ₩29,000 **그랜드페더링(평생 동결)**으로 보호한다.
- **연간 결제는 "2개월 무료"(연 16.7% 할인)**를 표준으로 한다. 시즌성이 강한 농산물 도메인 특성상, **제철 직전 연간 전환 캠페인**으로 현금흐름을 앞당긴다.
- **모델은 "Freemium + 사용량 페이월"**. 무료 체험(타임 트라이얼) 대신 **영구 무료 티어 + 사용량 한도 도달 시 업셀**이 본 도메인(셀러는 매달 반복 작업)에 적합하다.
- **확장 매출**: 추가 처리건수 애드온(종량), 추가 채널/사용자 좌석, 우선지원, 시즌 부스터 팩.
- **이탈 방지**: 해지 사유 수집 → 다운그레이드/일시정지/윈백 쿠폰 3단 리텐션 흐름. `past_due` 자동 복구(dunning) 시퀀스.
- **목표 지표**: 12개월 내 MRR ₩3,000,000+ (기본 시나리오), 유료 전환율 12~15%, 월 매출이탈(gross churn) <5%, NDR(순매출유지) ≥100%.

> **구현 정합성 메모**: 현재 코드의 `plans` 테이블(`code, name, price_krw, max_products, max_monthly_orders, features_json, active`)과 `quota.py`의 게이팅 키(`tracking`, `coupang_api`, `pricing`, `sales_history_days`)를 그대로 활용해 신규 티어를 **데이터로만 추가**할 수 있다. 코드 구조 변경 없이 row 추가 + features_json 키 확장으로 4단 전환이 가능하다(§9 참조).

## 1. 요금제 재설계 (4-Tier)

### 1.1 전체 요금표

| | **Free** | **Starter** | **Pro** ⭐가장 인기 | **Business** |
|---|---|---|---|---|
| **월 결제** | ₩0 | ₩19,000/월 | **₩39,000/월** | ₩99,000/월 |
| **연 결제** (2개월 무료) | ₩0 | ₩190,000/년 (₩15,833/월) | **₩390,000/년 (₩32,500/월)** | ₩990,000/년 (₩82,500/월) |
| **대상** | 체험·초소형(주말 셀러) | 단일품목 성장 셀러 | **주 타겟 P1 멀티채널 셀러** | 소규모 유통업자 P2·팀 |

| **다중 회신엑셀 운송장 자동매칭** (`tracking`) | ✗ | ✓ | ✓ | ✓ |
| **쿠팡 API 운송장 직접 등록** (`coupang_api`) | ✗ | ✗ | **✓** | ✓ |

### 1.2 디코이/앵커링 설계 의도

| 티어 | 심리적 역할 | 설계 의도 |
|---|---|---|
| **Free** | 미끼(Hook) | 가입 장벽 0. "엑셀만 올리면 발주서"라는 핵심 가치를 결제 없이 체감. 단, **운송장 자동매칭·쿠팡 API를 막아** 진짜 시간절감(왕복 자동화)은 유료에서만 경험하게 한다. |
| **Starter** | **디코이(Decoy)** | Pro를 매력적으로 보이게 하는 장치. "₩19,000인데 쿠팡 API도, 마진방어도 안 됨 → ₩20,000 더 내고 Pro 가면 다 됨"의 인식을 유도. 동시에 단일품목 셀러의 실제 진입가로도 기능. |
| **Pro** ⭐ | **타깃(Anchor의 수혜자)** | 가장 강조(하이라이트 박스, "가장 인기" 배지). 멀티채널 셀러가 필요한 모든 기능 포함. **여기로 모이게 설계.** |
| **Business** | **앵커(Anchor)** | ₩99,000이라는 높은 가격으로 Pro의 ₩39,000을 "저렴하게" 보이게 함. 동시에 P2 유통업자/팀이라는 실제 상위 수요를 흡수. 좌석 5개·20,000건으로 명백히 다른 세그먼트. |

**핵심 원리:** 가격표에 티어가 3~4개일 때 사용자는 **중간-상위(Pro)**를 고르는 경향(Goldilocks/극단 회피 효과). Business가 없으면 Pro가 "제일 비싼 것"이 되어 회피된다. Business를 둠으로써 Pro가 "중간의 합리적 선택"이 된다.

### 1.3 기능 게이팅 매트릭스 (코드 정합)

현재 `quota.py`는 `features_json`의 boolean/숫자 키로 기능을 막는다. 신규 4단을 위한 `features_json` 권장값:

| 키 | Free | Starter | Pro | Business | 비고 |
|---|---|---|---|---|---|
| `tracking` | `false` | `true` | `true` | `true` | 다중 회신엑셀 운송장 자동매칭 |
| `coupang_api` | `false` | `false` | `true` | `true` | 쿠팡 API 운송장 직접등록(왕복 제거) |
| `pricing` | `false` | `false` | `true` | `true` | 공급가 마진방어 모니터 |
| `sales_history_days` | `30` | `90` | `null`(무제한) | `null` | 대시보드 조회 기간 |
| `channels` (신규) | `1` | `2` | `3` | `3` | 연결 채널 수 — **신규 키, §9 마이그레이션 필요** |
| `seats` (신규) | `1` | `1` | `1` | `5` | 사용자 좌석 — **신규 키** |
| `temu_bulk` (신규) | `false` | `false` | `true` | `true` | 태무 대량등록 보조 |
| `priority_support` (신규) | `false` | `false` | `true` | `true` | 우선지원 SLA 태그 |

> **게이팅 UX 원칙:** 막힌 기능은 **숨기지 말고 "잠금"으로 노출**한다. 자물쇠 아이콘 + "Pro에서 사용 가능" 툴팁 → 클릭 시 업그레이드 모달. 기능의 존재 자체가 업셀 광고가 된다.

## 2. 프라이싱 심리 · 전략

### 2.1 앵커 가격 (Anchoring)

- 가격표 **좌→우를 저가→고가**로 배치. 사용자는 좌측부터 읽으며 Free→Starter에서 "싸다" 기준선을 잡고, Business(₩99,000)에서 천장을 본 뒤 **Pro(₩39,000)를 "균형점"으로 인식**한다.
- 영업 카피에 **"건당 비용" 환산 앵커**를 병기: "Pro ₩39,000 ÷ 월 5,000건 = **건당 7.8원**. 수기 변환 1건에 드는 시간(평균 30초~1분)을 생각하면…" → 가치를 시간/노동 단가로 재정의.

### 2.2 연간 결제 할인

- **표준: "2개월 무료" = 연 16.7% 할인** (월 12개월 → 연 10개월 가격). 퍼센트보다 **"2개월 공짜"**라는 표현이 전환율이 높다(손실회피 프레이밍).
- 월/연 **토글**을 가격표 상단에 배치. 토글을 "연간"으로 두는 것을 **기본값**으로 한다(연간 선택률↑). 토글 옆에 **"연간 결제 시 2개월 무료 🎁"** 라벨 상시 노출.
- 연 결제 시 각 카드에 **"₩78,000 절약"**(Pro 기준: 39,000×12 − 390,000 = 78,000)처럼 **절약 금액을 원화로** 강조.

### 2.3 "가장 인기" 강조 (Pro)

- Pro 카드만 **테두리 강조 + 배경 틴트 + 상단 "🌽 가장 많이 선택" 리본**. 다른 카드보다 살짝 크게(scale 1.05).
- CTA 버튼 색상 차등: Free=고스트, Starter=아웃라인, **Pro=솔리드 프라이머리(강한 색)**, Business="영업 문의" 또는 솔리드.

### 2.4 가격표 레이아웃 원칙

1. **4열을 한 화면에**(데스크톱), 모바일은 Pro를 최상단으로 재정렬.
2. **기능 행은 누적식**("Starter의 모든 기능 +")으로 표기해 상위 티어의 가치를 시각적으로 쌓는다.
3. **가격은 큰 폰트, 부가설명(/월, 부가세 별도 등)은 작게.**
4. **₩9,000/₩19,000/₩39,000/₩99,000** — 끝자리 9 가격(charm pricing). ₩40,000 대신 ₩39,000.
5. **FAQ를 가격표 바로 아래** 배치: 환불, 부가세, 채널 추가, 다운그레이드 시점 등 구매 직전 불안 해소.
6. **"부가세(VAT) 별도" 명시** — B2B 셀러는 세금계산서로 비용처리하므로 별도 표기가 신뢰를 준다.

### 2.5 가격 표기 카피 예시

```
[월간 / 연간 🎁2개월 무료]   ← 토글, 연간이 기본 선택

┌─────────┐ ┌─────────┐ ┌══════════┐ ┌─────────┐
│  Free   │ │ Starter │ ║  Pro ⭐  ║ │Business │
│   ₩0    │ │₩19,000  │ ║ ₩39,000  ║ │₩99,000  │
│         │ │  /월     │ ║   /월    ║ │  /월     │
│         │ │연 ₩190,000│║연 ₩390,000║│연 ₩990,000│
│         │ │         │ ║🌽가장 인기 ║│         │
```

## 3. 무료 → 유료 전환 퍼널

### 3.1 모델 선택: Freemium + 사용량 페이월 (Time-Trial 아님)

| 모델 | 적합성 | 결론 |
|---|---|---|
| **타임 트라이얼**(14일 Pro 무료 후 결제) | 시즌성 셀러는 비수기에 트라이얼 쓰고 떠남. 매일 쓰는 도구가 아님 | **부적합(주력 아님)** |
| **영구 Freemium + 사용량 페이월** | 셀러는 **매달 반복**으로 주문 처리 → 자연스럽게 한도 도달 → 업셀. 핵심가치를 무료로 맛보되 "진짜 자동화"는 유료 | ✅ **채택(주력)** |
| **하이브리드**: Free 유지 + **신규가입 시 14일간 Pro 기능 체험** | 가입 직후 운송장 자동매칭·쿠팡 API의 "왕복 제거" 가치를 강제로 경험시킴 → 14일 후 Free로 강등되며 상실감 유발 | ✅ **보조 채택(온보딩 부스트)** |

**근거:** 본 제품의 "아하 모먼트"는 *발주서 생성*이 아니라 **운송장 왕복 자동화(매칭+쿠팡 API 등록)**에서 온다. 이건 Free에서 막혀 있으므로, **신규 14일 동안만 풀어주는 하이브리드**가 전환의 핵심 레버다.

### 3.2 페이월 위치 (어디서 결제를 요구하나)

현재 `quota.py`는 한도 초과 시 **HTTP 402**, 기능 미허용 시 **HTTP 403**을 던진다. 이를 UX 페이월로 연결:

| 페이월 트리거 | 코드 위치 | UX |
|---|---|---|
| 월 처리건수 초과 | `check_order_quota` → 402 | "이번 달 50건을 모두 사용했어요. Pro로 올리면 5,000건" 모달 + 즉시 업그레이드 |
| 상품 등록 한도 | `check_product_limit` → 402 | "Free는 상품 1개까지. 품목을 더 등록하려면 Starter↑" |
| 잠금 기능 클릭 | `require_feature` → 403 | 운송장 자동매칭/쿠팡 API/마진방어 클릭 시 업그레이드 모달 |
| 대시보드 과거조회 | `sales_history_days` | 30일 이전 데이터에 블러 + "Pro에서 전체 기간 보기" 오버레이 |

### 3.3 사용량 한도 임박 업셀 트리거 (Dunning-up)

`get_monthly_usage(user_id)`의 `order_count`를 기준으로 **단계적 넛지**:

| 도달률 | 트리거 | 카피 예시 |
|---|---|---|
| **50%** | 조용한 진행바 표시 | (배너 없음) 대시보드 상단 사용량 게이지만 |
| **80%** | 인앱 배너(노란색) | "이번 달 한도의 80%를 사용했어요 (40/50건). 곧 처리에 제한이 생길 수 있어요. → **Pro로 업그레이드**" |
| **95%** | 상단 고정 배너(주황) + 이메일 | "한도 임박! 48/50건. 성수기 발주가 막히기 전에 미리 올려두세요." |
| **100%** | 처리 차단 모달(402) | "한도 도달. 지금 업그레이드하면 **즉시 이어서 처리**됩니다." (1클릭 결제) |
| **초과 후 재방문** | 로그인 시 모달 | "지난달 한도를 초과했어요. 이번 시즌엔 Pro가 더 경제적이에요." + 연간 제안 |

> **시즌 연동 넛지(농산물 특화):** 품목 제철 캘린더(§8)와 연동해, **제철 2~3주 전** Free/Starter 사용자에게 "곧 OO 성수기예요. 작년 이맘때 주문이 X배 늘었어요. 한도를 미리 올려두세요" 선제 업셀.

### 3.4 전환 유도 카피 뱅크 (실전)

- **가치 기반:** "운송장 입력에 매일 1시간? Pro면 클릭 한 번. 한 달이면 20시간을 아껴요."
- **손실회피:** "이번 달 한도 초과 시 발주서가 멈춥니다. 성수기 매출을 놓치지 마세요."
- **사회적 증거:** "멀티채널 셀러 10명 중 7명이 Pro를 씁니다."
- **앵커 환산:** "하루 1,300원. 커피 한 잔보다 싼 자동화."
- **시즌 긴급성:** "참외 성수기 D-14. 작년 이 시기 처리량 3배. Pro로 미리 대비하세요."

## 4. 업셀 / 확장 매출 (Expansion Revenue)

> 신규 획득(CAC)보다 **기존 고객 확장(NDR)**이 SaaS 수익의 복리 엔진. NDR ≥ 100% 목표.

### 4.1 애드온(Add-on) 카탈로그

| 애드온 | 가격(권장) | 대상 | 구현 메모 |
|---|---|---|---|
| **처리건수 부스터** | ₩10,000 / +1,000건 (월) | 한도 임박 Pro/Starter | `max_monthly_orders`를 구독 외 일회성/월간 가산. `usage` 비교 시 booster 합산 |
| **추가 채널** | ₩9,000 / 채널·월 | Starter(2→3채널) | `channels` 키 +1. 네이버/자사몰 연동(P2) 출시 시 핵심 확장 SKU |
| **추가 좌석** | ₩15,000 / 좌석·월 | Business 초과 팀 | `seats` 키 가산. 직원/외주 회계 분리 |
| **우선지원 Plus** | ₩20,000 / 월 | Starter/Pro | 카카오 채널 1:1 + 4시간 SLA |
| **시즌 부스터 팩** | ₩29,000 / 시즌(2개월) | 성수기 단기 폭증 셀러 | 특정 2개월간 건수·채널 상향. **농산물 시즌성 직격 SKU** |
| **양식 제작 대행** | ₩50,000 / 건(1회성) | 신규 품목·복잡 거래처 | 사람이 거래처 양식 매핑 셋업. 온보딩 마찰 제거 + 락인 |

### 4.2 사용량 기반(Usage-based) 과금 옵션

- **하이브리드 권장:** 구독(기본 한도 포함) + **초과분 종량**. 예) Pro 5,000건 포함, 초과 시 **건당 8원** 자동 과금(상한 캡 설정으로 청구서 쇼크 방지).
- **순수 종량(PAYG) 미니 플랜(선택):** 비정기 셀러용 "₩0 기본 + 건당 30원". 매달 안 쓰는 셀러를 이탈 대신 종량으로 유지.
- **청구 안전장치:** 월 종량 상한(cap), 초과 시 사전 알림, 예치(선불 크레딧) 옵션. `usage_logs` + `billing_events`로 정산 추적(이미 `log_usage` 존재).

### 4.3 연간 전환 업셀

- **월→연 인앤 배너:** 3개월 연속 결제한 월간 사용자에게 "연간으로 바꾸면 2개월 무료 = ₩78,000 절약" 원클릭 전환.
- **타이밍:** 카드 갱신일 D-3, 그리고 **제철 직전**(현금 선확보 + 시즌 중 이탈 방지).
- **다운그레이드 방어로서의 연간:** 해지 시도 시 "연간으로 바꾸면 실질 월 ₩32,500" 제안(§5.1).

## 5. 이탈 방지 (Churn Mitigation)

> 농산물 셀러는 **비수기 해지 → 성수기 재가입**을 반복할 위험이 크다. "해지" 대신 **"일시정지"**로 흡수하는 것이 LTV 방어의 핵심.

### 5.1 해지 흐름(Cancellation Flow) — 3단 리텐션

현재 `/api/billing/cancel`은 `cancel_at_period_end`만 설정(기간말 해지). 해지 **클릭과 실제 해지 사이**에 리텐션 단계를 삽입:

```
[해지하기 클릭]
   │
   ▼
① 해지 사유 수집 (필수, 단일선택)
   - 너무 비쌈 / 기능 부족 / 비수기라 안 씀 / 다른 도구로 이동 / 사업 중단 / 기타
   │
   ▼ (사유별 분기 오퍼)
② 맞춤 리텐션 오퍼
   - "너무 비쌈"        → 다운그레이드(Starter/Free) 또는 연간(실질 ₩32,500) 제안
   - "비수기라 안 씀"   → ⏸ 일시정지(최대 3개월, 과금 정지·데이터 보존) 제안  ★농산물 핵심
   - "기능 부족"        → 구체 기능 질문 → 로드맵 안내 + 1개월 50% 쿠폰
   - "다른 도구 이동"   → 윈백 쿠폰(다음 결제 30% off 3개월) + 1:1 상담 제안
   - "사업 중단"        → 데이터 익스포트 안내 + 재개 시 데이터 보존 약속
   │
   ▼ (그래도 해지)
③ 최종 확인 + 데이터/혜택 상실 고지
   - "기간 만료(현재 구독 종료일)까지는 그대로 사용 가능"
   - "이력/양식은 90일 보존 후 삭제" (재가입 시 복구)
```

### 5.2 다운그레이드 제안

- 해지 대신 **하위 티어 권유**가 항상 우선. Pro→Starter, Starter→Free.
- 다운그레이드는 **기간말 적용**(이미 낸 기간은 유지). 한도 축소로 데이터가 잘리지 않도록 **읽기는 허용, 신규 처리만 제한**.

### 5.3 일시정지(Pause) — 농산물 시즌성 대응 핵심 기능

- **최대 3개월 구독 일시정지**: 과금 중단, 데이터·설정 100% 보존, 기능은 Free 수준으로 다운.
- 비수기 셀러가 **해지(이탈)** 대신 **정지(유지)**를 택하게 만들어 성수기 자동 복귀 유도.
- 구현: `subscription.status = 'paused'` 상태 추가 + 스케줄러가 정지 기간 동안 과금 스킵, 만료 시 자동 재개 알림.

### 5.4 윈백(Win-back) 쿠폰

- 해지 완료자에게 **D+14, D+45** 2회 윈백 메일: "돌아오시면 첫 달 50% / 다음 3개월 30% off".
- **시즌 윈백:** 작년 해당 품목 성수기에 활동했던 이탈자에게 제철 D-21 "OO 시즌이 돌아왔어요" 재가입 캠페인.

### 5.5 결제 실패(`past_due`) Dunning 리커버리

현재 `scheduler.py`는 갱신 실패 시 `status='past_due'` + `billing_events('fail')` 기록. 여기에 **자동 복구 시퀀스** 추가:

| 시점 | 액션 | 채널 |
|---|---|---|
| 실패 즉시 | 카드 오류 안내 + 결제수단 업데이트 링크 | 인앱 배너 + 이메일 + 카카오 알림톡 |
| D+1 | 재시도(자동) | 백그라운드 |
| D+3 | 재시도 + "곧 기능이 제한됩니다" | 이메일 |
| D+5 | 재시도 | 백그라운드 |
| D+7 | **Grace 만료 → Free로 강등**(데이터 보존) | 이메일 + 인앱 |
| D+7~30 | 카드 갱신 시 **즉시 Pro 복구** | 원클릭 |

> **Grace period 7일** 동안은 `past_due`라도 기능을 끊지 않고 유지 → "막히기 전에 고쳐달라" 유도가 강제 차단보다 회수율이 높다.

## 6. 결제 UX 요구사항 (Toss Billing)

### 6.1 토스 빌링 위젯

- 현재 플로우(`/api/billing/subscribe`): 빌링키 발급(`/v1/billing/authorizations/issue`) → 첫 달 즉시 과금(`/v1/billing/{billingKey}`) → `upsert_subscription`. 이 구조 유지.
- 프런트: 토스 **결제위젯(빌링)** SDK로 카드 등록 → `authKey`+`customerKey` 수신 → 백엔드 `/subscribe` 호출. `customerKey`는 `balju-{user_id}` 규칙(현재 prefix `balju`).
- **플랜 선택 → 결제** 사이에 **주문 요약**(플랜·금액·주기·VAT·다음 결제일) 확인 화면 1단계.

### 6.2 월/연 토글 & 플랜 변경

- 가격표·결제 모달 모두 **월/연 토글** 일관 노출(기본 연간).
- **업그레이드(즉시 적용 + 비례정산 proration):** Starter→Pro 시 잔여기간 차액만 과금.
- **다운그레이드(기간말 적용):** 즉시 환불 대신 다음 주기부터 하위 요금.
- 플랜 변경 시 `plan_code`·`current_period_end` 갱신, `billing_events`에 `plan_change` 기록(신규 이벤트 타입).

### 6.3 영수증 · 세금계산서

- 모든 결제(`subscribe`/`renew`/booster)에 **이메일 영수증** 자동 발송.
- **세금계산서**: B2B 셀러 필수. 사업자번호 입력 → 월별/건별 전자세금계산서 발행(국세청 연동 또는 발행 대행). **VAT 별도** 정책 명시(₩39,000 + VAT ₩3,900 = ₩42,900).
- 결제 내역/영수증/세금계산서를 **셀프 대시보드**(PRD P1-2)에서 다운로드.

### 6.4 환불 정책

- **월간:** 결제 후 **7일 이내·미사용(해당 주기 처리 0건)** 시 전액 환불. 사용 시작 후 비례환불 없음(기간말 해지).
- **연간:** 14일 이내 전액 환불. 이후 **잔여 월 비례환불**(단, 이미 받은 "2개월 무료" 혜택 차감).
- **부스터/양식 대행:** 일회성·즉시 제공 항목은 **사용 후 환불 불가**, 미사용 시 7일 내 환불.
- 환불은 토스 결제취소 API로 처리, `billing_events('refund')` 기록.
- 정책을 가격표 FAQ·결제 화면에 **명문화**(분쟁 예방).

### 6.5 결제 실패 리커버리 UX

- 카드 만료/한도 초과 시 **인앱 상단 고정 배너** + **결제수단 업데이트 1클릭 모달**.
- 알림톡(카카오)으로 "결제 실패 → 7일 내 갱신 필요" 안내(국내 셀러는 카카오 도달률↑).
- §5.5 dunning 스케줄과 연동.

## 7. 수익 시뮬레이션 (MRR/ARR · LTV/CAC)

### 7.1 가정(공통)

- 유료 플랜 분포(전환자 중): **Starter 30% / Pro 55% / Business 15%** (Pro 집중 설계 반영).
- 가중평균 ARPU(유료): 19,000×0.30 + 39,000×0.55 + 99,000×0.15 = **₩41,250/월** (월간 기준, VAT 별도).
- 연간 결제 비중 40% 가정 시 현금흐름은 더 앞당겨지나, MRR 환산은 동일 ARPU로 단순화.
- 월 매출이탈(gross revenue churn): 5% 가정. 확장(expansion) 별도 미반영(보수적).

### 7.2 시나리오별 12개월 MRR/ARR

| 시나리오 | 누적 가입(12M) | 활성 무료 | 유료 전환율 | 유료 고객 | ARPU | **MRR** | **ARR** |
|---|---|---|---|---|---|---|---|
| **보수(Conservative)** | 600 | 480 | 8% | 38 | ₩41,250 | **₩1,567,500** | ₩18,810,000 |
| **기본(Base)** | 1,200 | 900 | 12% | 108 | ₩41,250 | **₩4,455,000** | ₩53,460,000 |
| **공격(Aggressive)** | 2,500 | 1,700 | 18% | 306 | ₩41,250 | **₩12,622,500** | ₩151,470,000 |

> 전환율은 활성 무료 사용자 기준. PRD §4 목표(3개월 15%+)는 본 시뮬의 기본~공격 사이.

### 7.3 확장 매출 반영 시(애드온/시즌 부스터)

- NDR 110% 가정(부스터·채널·연간 업셀): 기본 시나리오 MRR ₩4,455,000 → 12개월 후 확장 효과로 **실효 +10~20%**.
- **시즌 스파이크:** 농산물 성수기(예: 5~8월 참외·토마토, 9~11월 고구마) 2~3개월간 부스터/상위전환으로 MRR이 **평월 대비 1.3~1.6배** 출렁일 수 있음 → 연간 결제 유도로 평탄화.

### 7.4 LTV / CAC

- **LTV** = ARPU ÷ 월 churn = 41,250 ÷ 0.05 = **₩825,000** (gross; 마진 70% 가정 시 contribution LTV ≈ ₩577,500).
- **CAC 목표:** LTV:CAC ≥ **3:1** → 허용 CAC ≈ **₩190,000~270,000/유료고객**.
- **회수기간(Payback):** ≤ **6개월** 목표 (CAC ÷ ARPU). 콘텐츠/커뮤니티·기존 셀러 추천 등 **저비용 채널** 우선.
- **레버:** churn을 5%→3%로 낮추면 LTV가 ₩825,000→₩1,375,000으로 1.67배 → §5 리텐션 투자 최우선.

> 위 수치는 **계획용 가정**이며 실제 트래픽·전환 데이터(Supabase `usage_logs`/`billing_events`)로 분기마다 보정한다.

## 8. 농산물 도메인 특성 반영

### 8.1 제철 시즌성 (Seasonality)

- **수요 급증기 캘린더**를 제품에 내장(품목별 성수기). 예: 참외·토마토 5~8월, 고구마 9~11월, 콜라비 봄·가을, 두릅 봄.
- **시즌 전 선제 업셀**(§3.3): 성수기 D-14~21에 Free/Starter에게 한도 상향·부스터 제안.
- **시즌 부스터 SKU**(§4.1): 2개월 단기 상향. 연중 상시 Pro가 부담스러운 "단기 폭증형" 셀러 흡수.
- **연간 결제로 평탄화:** 시즌 직전 연간 전환 캠페인 → 비수기 해지 차단 + 현금 선확보.
- **일시정지(§5.3):** 비수기 이탈을 정지로 흡수 → 성수기 자동 복귀.

### 8.2 면세 농산물 정산

- 미가공 농산물(수박·참외·토마토·콜라비·고구마·두릅 등)은 **부가세 면세**(셀러의 판매 자체). 단, **본 SaaS 구독료는 과세 용역** → 셀러에게 **VAT 별도 + 세금계산서** 제공 필요(§6.3).
- 정산 대시보드(`sales_history`)는 셀러의 매출을 **면세/과세 구분** 표기(이미 마진계산기 부가세 0 처리 규칙 존재) → 셀러의 신고 편의 = 락인 요소.
- **차별화 카피:** "면세 농산물 정산까지 자동 구분. 세무사에게 그대로 넘기세요."

### 8.3 셀러 규모별 지불의사(WTP)

| 세그먼트 | 월 처리량 | WTP | 권장 티어 | 메모 |
|---|---|---|---|---|
| 주말·부업 셀러 | <50건 | 거의 0(무료 선호) | Free | 락인·바이럴 시드. 성장 시 Starter |
| 단일품목 전업 초기 | 50~800건 | ₩1~2만 | Starter | 가격 민감. 디코이지만 실수요 존재 |
| **멀티채널 전업(주 타깃)** | 800~5,000건 | **₩3~5만** | **Pro** | 시간절감 가치 명확. 가격탄력 낮음 |
| 소규모 유통/팀 | 5,000~20,000건 | ₩8~15만 | Business | 좌석·정산·우선지원에 지불. 협상 여지 |

> **인상 근거:** 주 타깃(멀티채널 전업)의 WTP가 ₩3~5만 구간이므로 Pro ₩39,000은 합리적. 가격 민감층은 Starter로 분리해 이탈을 막는다.

## 9. 구현/마이그레이션 메모 (코드 정합)

> **현 구조로 4단 전환은 "데이터 + features_json 키 추가"만으로 대부분 가능.** 큰 리팩터링 불필요.

1. **plans 테이블 시드 추가:** `db.py`의 seed 로직에 `starter`, `business` row 추가. 기존 `free`/`pro` 유지.
   - starter: `price_krw=19000, max_products=5, max_monthly_orders=800, features_json={tracking:true, coupang_api:false, pricing:false, sales_history_days:90, channels:2, seats:1}`
   - business: `price_krw=99000, max_products=null, max_monthly_orders=20000, features_json={... all true, sales_history_days:null, channels:3, seats:5}`
2. **신규 features_json 키:** `channels`, `seats`, `temu_bulk`, `priority_support`. `quota.py`에 `check_channel_limit`, `check_seat_limit` 헬퍼 추가(기존 `require_feature` 패턴 재사용).
3. **subscription.status 확장:** 현재 `active`/`past_due`. **`paused`** 추가(§5.3) + 스케줄러 정지기간 과금 스킵.
4. **연간 결제:** `plans`에 `billing_interval`(month/year) 또는 별도 `price_krw_yearly` 컬럼. 토스 과금 금액만 분기. `subscribe`/`scheduler` 금액 산정 분기 추가.
5. **proration·plan_change·refund·booster**: `billing_events` 이벤트 타입 확장(현 `subscribe`/`renew`/`fail`/`cancel_scheduled` → `+plan_change/refund/booster/pause/resume`).
6. **부스터(애드온):** `subscription`에 `extra_monthly_orders`, `extra_channels`, `extra_seats` 가산 컬럼 또는 별도 `addons` 테이블. `quota.py`의 한도 비교 시 합산.
7. **PRO_PLAN_PRICE 상수 → 플랜 테이블 단가로 일원화:** 현재 `config.PRO_PLAN_PRICE=29000` 하드코딩 → `plans.price_krw` 조회로 전환(다티어·인상 대응). 그랜드페더링은 기존 구독 row의 가격 동결로 처리.
8. **온프렘 영향 없음:** `DEPLOYMENT_MODE=onprem`/`DISABLE_BILLING`/`DISABLE_QUOTA` 경로는 그대로(라이선스 모델 별도).
